# 09 — Reconnecting ServiceNow after an AAP rebuild

**This document covers how to point a surviving ServiceNow instance at a freshly rebuilt AAP, by
updating two values per team: the event stream UUID and its token.**

> **When you need this.** Your AAP / EDA instance was deleted, re-provisioned, or failed to come
> back, and you are rebuilding it. Your ServiceNow PDI is intact.
>
> **Previous stage:** [01 — Provision AAP](01-provision-aap.md) and
> [03 — AAP / EDA setup](03-aap-eda-setup.md) get the platform back. **This doc is what comes after**:
> pointing the surviving ServiceNow side at the new AAP objects.
>
> **Time:** about 20 minutes for three teams, once AAP is up.

> **Any unfamiliar word?** Every term and acronym used in these guides is defined in the
> [Glossary](glossary.md) — including AAP, EDA, PDI, SCTASK, data pill, dot-walk, work note
> and `extra_vars`.

---

## 1. Why this stage exists at all

Nothing in AAP survives a rebuild. ServiceNow survives completely. So after a rebuild you have two
halves that are each individually fine and cannot talk to each other.

### One term, used throughout

A **route row** is a single record in the ServiceNow table `EDA Team Route` — one row per team. It
answers "where does this team's work get sent?" by holding that team's event stream address and the
credential used to reach it. You will edit one route row per team in §4. The full column list is
there too.

### What actually breaks

Two values per team break, and they are the only two:

| Value | Lives in AAP as | Lives in ServiceNow as | Why it breaks |
|---|---|---|---|
| Event stream **UUID** | the stream's POST URL | `event_stream_uuid` on the route row | regenerated per stream, every rebuild |
| Event stream **token** | the Event Stream Credential | the API Key credential on that team's Connection & Credential Alias | regenerated every rebuild. **One per team, or one shared** — [03 §2.9](03-aap-eda-setup.md) |

Everything else **on the ServiceNow side** is untouched — the scoped app, the three tables, the
Action, its three steps, the Flow, the assignment groups, and the route rows themselves. In
ServiceNow you are editing **two fields per team**, not rebuilding anything.

> ⚠️ **One thing outside ServiceNow also dies: your AAP Personal Access Token.** Anything scripted
> against AAP, including `scripts/verify_team.py`, needs a new one — see §2 step 16.

> ⚠️ **How many tokens you are replacing depends on a choice, not on a rule.** These guides default
> to **one token per stream**, which means one ServiceNow Connection & Credential Alias per team —
> three teams, three aliases. **That is a recommendation, not a constraint:** nothing in EDA compares
> tokens across streams, so a single shared token across every stream is supported, and then you
> replace **one** value instead of N. The trade-off — a leak is valid everywhere, and rotation is
> lockstep — is in
> [design decisions §1.5](design-decisions.md#15-tokens-one-per-stream-by-default-or-one-shared--a-real-choice).
>
> 🔴 **The UUID is different: it is always per stream.** It is the path that selects which stream a
> POST lands on, so every one of them is regenerated by a rebuild and every one has to be replaced.
> That part is not a choice.

## 2. Before you touch ServiceNow: finish AAP properly

The single most common way to lose this afternoon is to rebuild AAP incompletely, reconcile
ServiceNow against it, and then have to do the reconciliation twice.

Work through [01 — Provision AAP](01-provision-aap.md) and
[03 — AAP / EDA setup](03-aap-eda-setup.md) in full. The complete object list, in dependency order:

The order below is a dependency order, not a preference — each step needs something the previous one
created.

**First, once for the whole instance:**

1. The custom **`ServiceNow` credential type** ([03 §1](03-aap-eda-setup.md)). Easily missed, because
   it is the only global object and nothing in the per-team steps reminds you of it.

**Second, before you create anything at all in EDA:**

2. Re-apply the **resource-limit patch** ([01 §4](01-provision-aap.md)). The default 400Mi gets the
   clone worker killed for running out of memory, which surfaces as an EDA project sync stuck on
   "Pending". Applying this after you have already created the project means redoing the project.
3. Re-apply the **`revisionHistoryLimit` cap**
   ([AAP platform troubleshooting §5](aap-platform-troubleshooting.md#5-on-a-brand-new-sandbox-apply-both-fixes-first)).
   A rebuild restores the default of 10, and on a quota-limited sandbox that refills the 30-ReplicaSet
   cap after a handful of changes — at which point **every** AAP Deployment loses its pods. Do it
   after step 2, so the ReplicaSets the memory patch creates are the ones kept.

**Then, for each team in turn:**

4. Organization
5. Inventory
6. Controller credentials
7. Controller project
8. Job template — **tick prompt-on-launch**. It is mandatory, and omitting it fails silently
9. EDA credentials — the controller credential and the Red Hat registry credential
10. Decision Environment
11. EDA project — the rulebook must **already be pushed to the remote**, because the project can only
    offer a rulebook the remote actually has
12. Event stream **token** — generate it and keep it somewhere you can paste from. One per team, or
    one shared across all of them ([03 §2.9](03-aap-eda-setup.md))
13. Event stream **credential**
14. Event **stream** — this is where the new UUID is minted
15. Rulebook **activation**, including the event-stream source mapping on page 2

**Finally, once AAP is up:**

16. **Re-mint your AAP Personal Access Token.** A Personal Access Token (PAT) is a long-lived
    credential used instead of a password by anything scripted. The rebuild invalidated the old one,
    so `scripts/verify_team.py` in §6.2 will fail to authenticate until you replace it. Mint a new
    one in AAP under your user's **Tokens**, and update wherever you keep
    `SANDBOX_AAP_PAT_TOKEN`.

> ⚠️ **Once a stream exists, PATCH the organization rather than recreating the stream.**
> Recreating or moving a stream between organizations regenerates its UUID, and every route row
> pointing at it goes stale. If you need to change a stream's org, patch the org.

## 3. Collect the new values

For each team, read back the stream's POST URL and note the UUID segment. The path is:

```
eda-event-streams/api/eda/v1/external_event_stream/<uuid>/post/
```

Record them somewhere scratch — **not in this repo**:

| Team | Stream name | New UUID | New token |
|---|---|---|---|
| team-a | `sn-team-a` | | |
| team-b | `sn-team-b` | | |
| team-c | `sn-team-c` | | |

> 🔴 **Do not commit UUIDs or tokens.** This repo is public. UUIDs are effectively endpoint
> credentials: anyone holding one can POST events into your automation. Keep them in the route table
> and the credential alias, which is exactly where they belong — in ServiceNow, behind ACLs.

---

## 4. Update the route rows

The routing table is `x_661661_james_tes_eda_team_route` (**EDA Team Route**). One row per team,
keyed on **assignment group**.

![Route table columns](images/70-sn-route-table-columns.png)

| Column | Type | Role |
|---|---|---|
| `assignment_group` | Reference → `sys_user_group` | **the routing key** — matched against the record's assignment group |
| `event_stream_uuid` | String | goes into the REST step's resource path |
| `connection_alias` | Reference → `sys_alias` | the team's Connection & Credential Alias, carrying the token |
| `event_stream_name` | String | human label, for your sanity when reading rows |
| `team_code` | String | the display column; also sent in the payload as `target_team` |
| `active` | True/False | lets you park a team without deleting the row |

![Route table rows](images/71-sn-route-table-rows.png)

For each team, open its row and replace **`event_stream_uuid`** with the new value from §3.

The field holds the UUID **only** — not the whole URL, and no slashes. So if §3 gave you this URL:

```
https://aap.example.com/eda-event-streams/api/eda/v1/external_event_stream/1a2b3c4d-5e6f-7890-abcd-ef1234567890/post/
```

then the value you paste into `event_stream_uuid` is:

```
1a2b3c4d-5e6f-7890-abcd-ef1234567890
```

> ⚠️ **Pasting the full URL is the most common mistake here.** The REST step builds the path around
> this value, so a full URL produces a malformed request rather than a clear error.

That is the only field on this table a rebuild invalidates — the assignment group, team code and
alias reference all still point at live ServiceNow records, so leave them alone.

---

## 5. Update the tokens on the aliases

One **Connection & Credential Alias** — a ServiceNow object bundling "where to send a request" with
"what credential to send it with" — per team, each holding that team's token:

| Team | Alias record name | How it appears internally |
|---|---|---|
| team-a | `Ansible EDA Team A Alias` | `x_661661_james_tes.Ansible_EDA_Team_A_Alias` |
| team-b | `Ansible EDA Team B Alias` | `x_661661_james_tes.Ansible_EDA_Team_B_Alias` |
| team-c | `Ansible EDA Team C Alias` | `x_661661_james_tes.Ansible_EDA_Team_C_Alias` |

> ℹ️ **Both forms are correct.** You search for the spaced name in the alias list; ServiceNow renders
> the underscored, scope-prefixed form in the route table and quotes it in
> `Unable to load connection with alias ID:` errors. Seeing underscores is not a sign you named it
> wrongly.

![Credential alias](images/40-sn-credential-alias.png)

For each one, open its credential record and replace the token with the new value.

> 🔴 **Store the token bare. No `Bearer ` prefix.**
> AAP compares the incoming header value against the stored token **verbatim**, and nothing adds a
> scheme for you. A prefix therefore makes it not match, rejecting the event with a **`403`**
> that looks exactly like a wrong password — and you will spend an hour on it. The header name is
> `Authorization` and the value is the token alone. There is a separate **API Key Prefix** field on
> the ServiceNow credential; leave it empty.

> ⚠️ **Never add an `Authorization` header manually to the REST step.** The alias supplies it.
> Adding your own produces two, and the request is rejected.

## 6. Verify, in increasing order of scope

Test the cheap things first. Each step isolates one layer, so a failure tells you where you are.

**6.1 — The stream and token, with no ServiceNow involved.** Use the ready-made `curl` in
[07 §2](07-end-to-end-test.md#2-layer-2--the-event-stream-and-token), substituting this team's new
UUID and token. A `200` means the stream and token agree; a **`403`** means the token is wrong or
carries a prefix, and a **`400`** means the UUID is wrong (or no header was sent) — see
[10 §3.2](10-troubleshooting.md#32-work-note-shows-400-or-404--the-event-stream-uuid).

**6.2 — The route rows against live AAP.** Re-mint your AAP Personal Access Token first — the
rebuild invalidated the old one, and the checker authenticates with it:

```bash
cd /path/to/Ansible_EDA_Test
export AAP_GATEWAY="https://<your-aap-host>"
python3 scripts/verify_team.py --team team-c
```

Full invocation, the environment variables it needs, how to read its output, and its known
`team_code` limitation are all in [08 §5](08-routine-ops.md#5-verify-mechanically-before-you-test-by-hand).

**6.3 — The job template alone.** Launch it manually in AAP with sample `extra_vars` —
[07 §3](07-end-to-end-test.md#3-layer-3--the-job-template-alone) has the values to paste.

**6.4 — The full chain.** [07 §4](07-end-to-end-test.md#4-layer-4--the-full-chain) lists the four
places to look, in order.

> 🔴 **Your test record must actually match the trigger**, or the flow never starts, there is no
> execution to inspect, and nothing anywhere reports an error. On the Incident flow that includes the
> **Caller**. Diagnostic procedure: [10 §2.1](10-troubleshooting.md#21-no-flow-execution-at-all).

## 7. What to do if a team still does not route

Work down this list; it is ordered by how often each one is the cause.

| Symptom | Cause | Fix |
|---|---|---|
| Flow never ran — no execution at all | Record does not match the trigger condition | Check the trigger, not the flow |
| Work note says the request was not sent, REST reported no error | No route row matched | Check `assignment_group` and `active` on the row |
| `403` from the stream | Wrong token, or a prefix on it | §5 |
| `400` from the stream | Stale `event_stream_uuid` on the route row — **the usual post-rebuild failure** | §4 |
| `Unable to load connection with alias ID:` | `connection_alias` empty on the matched route row | §4 |
| Event accepted, `200`, but no job runs | The rulebook's condition does not match the payload | The `event_type` value — see [05](05-servicenow-action.md) |
| EDA project stuck on "Pending" | Default worker OOMKilled at 400Mi | §2, the resource patch |
| AAP itself is down — no pods at all | The namespace's ReplicaSet quota is full | [AAP platform troubleshooting §4](aap-platform-troubleshooting.md#4-every-aap-pod-is-gone-and-rollouts-fail-on-quota) |

Fuller catalogue in [10 — Troubleshooting](10-troubleshooting.md). For failures in the cluster
*underneath* AAP rather than in the pipeline, see
[AAP platform troubleshooting](aap-platform-troubleshooting.md).

## 8. Tearing a stream down later

If you ever need to remove a stream, the order is forced:

1. the **activation**
2. the **stream**
3. the **credential**

> ⚠️ **Activation deletion is asynchronous.** Deleting the stream immediately after the activation
> returns `409 "... is being referenced by 1 activation(s)"` even though the activation is gone from
> the UI. Wait roughly 15 seconds and retry. The order is not wrong — you were just early.

## 9. What this stage does not cover

- **Rebuilding ServiceNow.** If the PDI itself is gone, start at
  [02 — Provision the PDI](02-provision-pdi.md). A PDI is reclaimed after about ten days of
  inactivity and you lose everything on it, so keep the scoped app in an Update Set or in source
  control.
- **Adding a new team.** That is [08 — Routine ops](08-routine-ops.md), not this doc. This doc
  assumes the teams already exist in ServiceNow and only their AAP endpoints moved.

**Next:** nothing — if §6.4 passes, you are back to where you were before the rebuild.

## Checkpoint

- [ ] Every object in §2's list exists, including the global credential type and the re-minted PAT
- [ ] The sizing patch was applied **before** any EDA project was created
- [ ] Each team's route row holds the new `event_stream_uuid` — the UUID only, no URL
- [ ] Each team's credential holds the new token, stored **bare**
- [ ] [§6.1](#6-verify-in-increasing-order-of-scope) returns `200`
- [ ] `verify_team.py` exits zero
- [ ] A real record routes end to end, and the other teams' counters did not move
